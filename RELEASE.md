# Shipping "The Secret Cafe" to Google Play

This is the release runbook for the Android build of the Next.js POS app.
Everything in the "Already set up" section is done — you do not need to redo it.

### Back up the signing key NOW

Two files decide whether you can ever update this app:

```
android/keystore/secretcafe-upload.jks
android/keystore.properties
```

Put both in a password manager or encrypted cloud folder. If you lose them you cannot publish an
update under the same listing without filing a *reset upload key* request with Google Play support.

The keystore was generated with the password `SecretCafeUpload2026-Kp7Wv3Nq9Rt`. To use your own
instead, delete both files and regenerate:

```bat
mkdir android\keystore
keytool -genkeypair -v -keystore android\keystore\secretcafe-upload.jks ^
  -alias secretcafe-upload -keyalg RSA -keysize 4096 -validity 10000 ^
  -dname "CN=The Secret Cafe, O=The Secret Cafe, C=IN"
```

Then update `storePassword` / `keyPassword` in `android/keystore.properties` to match.

## 2. Build a release

```bat
npm run build:android     :: web export + strip service worker + cap sync
npm run release:android   :: the above, then a signed .aab
```

Output: `android/app/build/outputs/bundle/release/app-release.aab`

That `.aab` is the only file you upload. Google Play re-signs it with the real app-signing key
("Play App Signing", on by default), so the `.jks` above only ever signs the upload.

To test the release build on a device or emulator first:

```bat
android\gradlew.bat -p android assembleRelease
adb install -r android\app\build\outputs\apk\release\app-release.apk
```

Debug builds for day-to-day work are unchanged: `npx cap run android`.

## 3. Play Console submission

### 3.1 Create the app

1. Sign in at <https://play.google.com/console> with the Google account that will own the app.
   Use a business/team account if more than one person needs access — an app cannot be moved
   between accounts later.
2. **Create app** → App name `The Secret Cafe`, default language, type **App**, **Free**.
3. Accept the Developer Program Policies and the US export declaration.

### 3.2 Fill the "App content" checklist

Play blocks the release until every item is green. Most are short forms:

| Item | What to answer for this app |
| --- | --- |
| Privacy policy | Required. Needs a public URL — see §4. |
| App access | All functionality is behind a login, so declare *"All or some functionality is restricted"* and supply a working test account for the reviewer. **If you skip this, review will be rejected.** |
| Ads | No. |
| Content rating | Complete the questionnaire (category: Utility / Business). |
| Target audience | 18+ or 13+; this is a staff tool, not child-directed. |
| News app | No. |
| Data safety | Declare what you collect — see §4. |
| Government app | No. |
| Financial features | Only if you process payments inside the app. |
| Health | No. |

### 3.3 Upload the bundle

1. **Testing → Internal testing → Create new release**.
2. Upload `app-release.aab`. Play shows the upload-key fingerprint and offers to enrol you in
   Play App Signing — accept.
3. Add yourself as an internal tester, roll out, and install through the opt-in link.
   This verifies the signed build end to end before anything is public.
4. When happy: **Production → Create new release**, upload the same `.aab` (or promote the
   internal one), add release notes, and roll out. First submissions typically take a few days
   to review.

You cannot publish with a personal account created after Nov 2023 without completing the
**closed test with 12+ testers for 14 days** requirement — check your account status early,
it is the most common surprise.

### 3.4 Store listing assets

Have these ready before you start the listing:

| Asset | Requirement |
| --- | --- |
| App icon | 512×512 PNG, 32-bit, no alpha |
| Feature graphic | 1024×500 PNG/JPEG — required |
| Phone screenshots | 2–8 images, 16:9 or 9:16, min 1080px on the short side |
| Short description | ≤ 80 characters |
| Full description | ≤ 4000 characters |

For the icon you can reuse `assets/icon-only.svg` (it is the same mark). Screenshots can be taken
straight off the emulator:

```bat
adb shell screencap -p /sdcard/shot.png && adb pull /sdcard/shot.png .
```

## 4. Privacy policy and Data safety

Both are mandatory and both must match what the app actually does.

The app already takes reasonable precautions: `android:allowBackup="false"` is set in the
manifest so session tokens and cached order data cannot be extracted through `adb backup`.

Write a privacy policy page (a public URL — a hosted page, GitHub Pages, or a Notion page are all
accepted), then in **Data safety** declare, at minimum:

- **Data collected:** email address and name (staff accounts), plus whatever customer/order data
  is stored server-side.
- **Data shared:** check your backend — if it runs on a third-party host, declare it.
- **Security practices:** "Data is encrypted in transit" if your API is HTTPS.
- **Deletion request:** provide a way for users to request deletion.

Keep the policy and the Data safety form consistent. A mismatch is a common cause of rejection.

## 5. Publishing an update

Every upload needs a `versionCode` higher than the last. Edit `android/app/build.gradle`:

```gradle
versionCode 2          // must increase by at least 1 every upload
versionName "1.1"      // what users see
```

Then re-run `npm run release:android` and upload the new `.aab`.

## 6. Gotchas that will bite you

**JDK must be 21.** Capacitor 8 compiles its Android library with Java 21. `android/gradle.properties`
pins `org.gradle.java.home=C:/Program Files/Zulu/zulu-21` because this machine's `JAVA_HOME` points
at a JDK 17 install, which produced `error: invalid source release: 21`. If you move the Zulu
install, update that line — or repoint `JAVA_HOME` at JDK 21 and delete it.

**`npx cap sync` does not rewrite `android/app/src/main/res/values/strings.xml`.** The app name
lives there and is only written when the platform is first added, so changing `appName` in
`capacitor.config.ts` alone is not enough. If the label ever reverts to `secretcafe`, re-apply the
edit to `strings.xml`.

**Never run `npx cap add android` on this project.** It would regenerate the platform and wipe the
signing config, icon, splash, `strings.xml`, and manifest changes.

**Don't commit the keystore.** `android/.gitignore` excludes `*.jks`, `*.keystore`, `keystore/` and
`keystore.properties`. Verify with `git check-ignore -v android/keystore/secretcafe-upload.jks`.

**`android/.gradle/` and `android/build/` are tracked by git.** They were committed before the
ignore rules existed, so every build shows up as a large noisy diff. To clean it up once:

```bat
git rm -r --cached android/.gradle android/build android/app/build
git commit -m "Stop tracking Gradle build output"
```

**Splash and icon regeneration.** After editing anything in `assets/`, run:

```bat
npm run icons:android
```

Note that `@capacitor/assets` wraps both adaptive-icon layers in
`<inset android:inset="16.7%"/>`, which scales the artwork to 66.6% of the 108dp canvas. The SVGs in
`assets/` are sized for that, so keep the mark around 84% of the source canvas rather than
full-bleed.
